# Tasks delegated to Codex

Work items carved out of the 0.5.0 release that are self-contained enough to run
in a separate worktree. Codex works in `C:\dev\web\deskmate-codex` on
`codex/work`; the protocol is in `AGENTS.md`. None of these may be merged or
pushed without Jakub saying so.

Each task states what "done" means, because none of them can be verified by the
agent that writes them - they all need real hardware or a real Home Assistant.

## C1 - Real COM toast activator (fallback for the 0.5.0 fix)

**Why.** 0.5.0 makes action buttons render by registering a toast activator
CLSID and pointing the AUMID at it. Clicks are handled over the `deskmate:`
protocol, so nothing has to implement the COM interface. If a future Windows
build tightens this and requires the server to actually answer, the buttons stop
working again.

**Scope.** Implement `INotificationActivationCallback` in `src-tauri`, using the
`windows` crate already in the tree. Register the class factory when the process
starts with `-ToastActivated` or `-Embedding`, hand the activation arguments to
the existing `action_tx` channel, and exit when the reference count drops.
Keep the protocol path as the primary route; the COM path is a fallback, not a
replacement.

**Constraints.** No `ring`, no `openssl`, no C toolchain - `cargo tree` must stay
free of them so ARM64 keeps building. `cargo check` and `npx tsc --noEmit` green.

**Done when.** A toast sent from Home Assistant with two action buttons renders
them, and clicking one produces the `deskmate_link_notify_action` event, on both
x64 and ARM64. Verified by Jakub on hardware, not by the agent.

## C2 - Cross-implementation test vectors for cascade encryption

**Why.** The single-layer frame codec already has a fixture generated by the
Python `FrameCodec` and checked by a Rust test. Cascade encryption added a second
cipher on both sides with no equivalent coverage, and a mismatch there fails at
runtime as an authentication error with no useful detail.

**Scope.** Extend the existing fixture to cover cascade frames: same pairing key,
a separate cascade key, both directions, several counters. Generate it with the
Python implementation in `custom_components/deskmate_link/crypto.py` and assert
in Rust that decryption, direction separation and replay rejection all match.
Add the reverse direction too - a Rust-generated vector verified in Python -
because the current fixture only proves one direction.

**Done when.** `cargo test` covers cascade frames and fails if either side
changes its HKDF labels, AAD or nonce construction.

## C3 - CI for builds and Home Assistant validation

**Why.** Installers are built by hand on one laptop, and the integration has
never been run through the validators HACS and Home Assistant expect. Both are
mechanical and belong in CI.

**Scope.** A GitHub Actions workflow that, on tag:

- builds NSIS installers for `x86_64-pc-windows-msvc` and
  `aarch64-pc-windows-msvc`, publishes them as release assets with a
  `SHA256SUMS.txt`;
- runs `home-assistant/actions/hassfest` and `hacs/action` against the
  repository on every push, so a malformed `manifest.json` or `hacs.json` is
  caught before a user hits it.

Do not add signing. There is no certificate, and pretending otherwise in CI
config would be worse than the current honest SmartScreen warning.

**Done when.** A tag produces a draft release with four assets, and the two
validation jobs pass on `main`.
