# Deskmate 0.6.0 - Link protocol v2, one pairing code, no more duplicates

Deskmate Link moves to protocol v2 with forward secrecy, pairing becomes a
single code you paste once, and re-pairing a computer no longer leaves a second
device with `_2` entities behind. Desktops with a discrete GPU stop seeing their
hardware sensors vanish and come back.

## Fastest setup (new install, about 5 minutes)

1. **Home Assistant:** in HACS open the three-dot menu (top right) →
   *Custom repositories*, paste `https://github.com/JakubWawrzola/deskmate`,
   type *Integration*, *Add*. Search HACS for **Deskmate Link**, download it,
   restart Home Assistant. (HACS does not add an unknown repository from a
   link, so an "Open in HACS" button only works after this step.)
2. **Home Assistant:** *Settings → Devices & services → Add integration →
   Deskmate Link*, confirm. Copy the pairing code that starts with `DMP1.`.
3. **Windows:** install `Deskmate_0.6.0_x64-setup.exe` (normal PC) or
   `Deskmate_0.6.0_arm64-setup.exe` (Snapdragon). On first launch paste the
   code and choose **Save & connect**. The key and the addresses come from the
   code; the status line should read `Connected (Link)`.

The code contains the addresses Home Assistant knows about itself
(*Settings → System → Network*). If the address field stays empty, fill in
Home Assistant's local and external URLs there and add the integration again
(the same entry and code are reused), or type the address by hand:
`ws://homeassistant.local:8123` at home, `wss://your-domain` from outside.

## Upgrading from 0.4 or 0.5 (order matters)

1. **Update the integration first.** HACS → Deskmate Link → Update (or copy
   `custom_components/deskmate_link` into `config/custom_components/`), then
   restart Home Assistant. Computers still on 0.5 keep working.
2. **Then install 0.6.0 on each computer**, over the old version. Settings and
   the stored key are kept. The computer reconnects with protocol v2.
3. Nothing else to do. From the first v2 connection that entry refuses the old
   protocol. If an earlier pairing attempt left a duplicate entry for the same
   computer, it is merged on that first connection: entities keep their IDs and
   history, the extra entry disappears.

Doing it the other way round (new app, old integration) fails with
`Link rejected`, because integrations before 0.6.0 do not understand v2.

| Integration | Deskmate 0.5 | Deskmate 0.6 |
|---|---|---|
| 0.5.0 | works | rejected |
| 0.6.0 | works until that computer connects with 0.6 | works |

Coming from MQTT: [docs/MIGRATION.md](MIGRATION.md). Setting up with an AI
assistant: [docs/AI-DEPLOY.md](AI-DEPLOY.md).

## If it does not connect

Deskmate's status line names the cause:

| Status | Fix |
|---|---|
| `Link rejected ...` | Key does not match, or the integration is older than 0.6.0. Update it, or pair again. |
| `Link clock mismatch ...` | Clocks differ by more than 90 s. Windows: *Settings → Time & language → Sync now*. Common on dual-boot PCs. |
| `... cascade encryption is on at one end only` | Enable or disable cascade on both sides. |
| `... does not accept this protocol version` | Update the integration to 0.6.0. |
| `Link locked out ...` | Too many failed attempts; clears within five minutes once the cause is fixed. |

## Highlights

**Protocol v2.** Each connection runs an ephemeral X25519 exchange, mixed with
the pairing key in HKDF. Before, anyone who recorded traffic and later got the
pairing key, for example from a Home Assistant backup, could decrypt every
recorded session. Now a leaked key does not open old recordings. The handshake
MAC covers the whole transcript, both public keys and the cascade flag, with a
length-prefixed encoding. Test vectors generated by the Python integration are
checked by the Rust tests.

**One pairing code.** The integration shows `DMP1.…`, which carries the key and
Home Assistant's addresses. Adding the integration again while an entry is
still waiting for pairing shows the same code instead of creating another entry.

**No more duplicated computers.** Re-pairing used to leave two entries on one
device and duplicate every entity with a `_2` suffix. The entry the computer
actually connects with now takes over the old entry's entities and removes it.

**Stable hardware sensors.** A single failed PDH or WMI read withdrew GPU and
temperature entities, and Home Assistant deleted and recreated them on the next
tick. PDH reads now retry when the GPU engine list grows mid-read, and a sensor
is withdrawn only after about 2.5 minutes without data.

**Failures say what is wrong.** Wrong key, wrong clock, cascade mismatch and
old integration each get their own message. A wrong clock used to look exactly
like a wrong key.

## Security

- Link protocol v2 with forward secrecy, full-transcript MAC and a one-way
  upgrade per entry (no downgrade to v1 after the first v2 connection).
- Toast buttons carry a single-use token. A `deskmate:action?...` link opened by
  a web page or another program can no longer fire Home Assistant automations.
  Buttons on toasts shown before Deskmate restarted stop working by design.
- Content Security Policy for the app window.
- Pairing and session keys are wiped from memory after use.
- `ws://` is accepted only for LAN, `.local`, `.lan`, single-label and
  Tailscale addresses; internet-facing addresses need `wss://`.
- Saving settings validates every key before writing any of them, and renaming
  the node keeps the pairing key, cascade key and Home Assistant token.
- Downloaded toast images are deleted ten minutes after display.
